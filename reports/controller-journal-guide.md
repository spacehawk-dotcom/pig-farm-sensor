# 환기앱 실제 설정 기록과 추천

환기 시뮬레이션 `simu.html`에서 배치를 선택한 뒤 상단 **📝 실제 설정 기록 · 데이터 기반 추천** 바로가기를 누릅니다. 선택 배치의 기존 기록을 그대로 조회·저장·분석합니다. 환기앱 `temp.html`에서는 이 영역을 제거했습니다.

## 배치별 공유 설정

환기앱 상단 **4단계 분할 제어 현재 적용 설정** 표에서도 각 배치의 1~4그룹 온도와 1·2그룹 최소환기 %를 직접 수정할 수 있습니다. 입력칸에서 Enter를 누르거나 다른 곳으로 이동하면 해당 배치·항목만 저장됩니다. 입력 중에는 실시간 화면 갱신이 작성 중인 값을 덮어쓰지 않습니다.

표에서 입력을 마치면 해당 항목만 Firebase 배치 문서의 `ventilationOverrides`에 저장합니다. 사육현황과 환기 시뮬레이터에서도 같은 값을 읽습니다. 수정한 항목은 고정되며 수정하지 않은 항목은 계산값을 따릅니다.

공유 설정은 실제 팬 제어 명령이 아니며, 자동으로 실제 운전 이력으로 기록하지 않습니다. 시뮬레이션 앱의 관찰 기록 폼에는 현재 사육현황의 공유 설정이 초기값으로 채워집니다. 가상 시나리오 입력은 실제 기록의 초기값에 반영하지 않습니다. 과거 관찰 값을 편집 중이면 자동 갱신으로 덮어쓰지 않습니다. 실제 컨트롤러와 대조 후 누적 저장합니다.

## 기록 방법

1. 컨트롤러에서 읽은 그룹별 설정온도, 최소·최대 전압 %, 편차를 입력합니다. ‘현재 공유값 입력’은 입력 보조 기능으로, 반드시 실제 값과 대조합니다.
2. 실제로 같은 설정과 사육·설비 조건이 유지된 관찰 시작·종료를 한국시간으로 입력합니다. 처음에는 같은 시각으로 현재 설정만 기록해도 됩니다. 이 기록 자체는 온도 반응 분석에 사용되지 않습니다.
3. 두수·체중·일령, 입기구·순환·난방 상태를 확인합니다. 기침·몰림 등 관찰 상태는 미확인이 기본값입니다. 실측한 전체 배기량이 있으면 별도로 입력합니다. 전압 %를 풍량으로 변환하지 않습니다.
4. 확인란을 선택하고 누적 저장합니다. 처음 기록 후 다음날 ‘최근 기록 이어서 입력’으로 관찰 기간을 기록할 수 있습니다. 그 사이 설정이 바뀌었다면 구간을 나누고, 두수·체중·설비 상태가 크게 바뀐 기간도 나눕니다. 한 기록은 최대 7일입니다.
5. 저장 결과를 확인합니다. 클라우드 실패 시 기기 저장 상태를 명확히 표시하며, ‘미전송 기록 재전송’과 JSON 내보내기를 제공합니다.

Firestore의 `farms/sungamfarm/ventilation_records/{UUID}`에 새 문서로 저장합니다. 기존 권장값 고정 저장과 별도입니다. 실제 설정을 자동으로 읽거나 팬을 제어하지 않습니다. 브라우저 localStorage에도 복사본을 저장하므로 같은 기기·같은 주소에서 복구할 수 있습니다. 기기 저장만 된 상태에서 브라우저 데이터를 삭제하면 잃을 수 있으므로 클라우드 전송 상태를 확인하거나 JSON으로 내보냅니다. 기존 Firebase 권한을 사용하며 권한 규칙은 변경하지 않습니다.

## 추천 방법

현재 입기구·순환·난방 상태와 목표 실내 온도 범위를 입력하고 최근 1년 기록 분석을 누릅니다. 목표 초기값(현재 계산 온도~+2℃)은 사용자가 확인할 입력 제안이며 자동 확정한 적정 온도가 아닙니다.

- 같은 돈방과 동일한 설비 상태 문자열만 비교합니다.
- 현재 사육현황의 두수·예측 체중 대비 ±20%, 최근 6시간 평균 외기 대비 ±3℃인 관찰을 비교합니다.
- 한국시간 00~06/06~12/12~18/18~24의 같은 시간대에 시작한 관찰 창을 비교합니다.
- 각 관찰 시작 후 30분을 제외하고 6시간 단위로 평가하므로 최소 6시간 30분 이상 기록이 필요합니다.
- 내·외기 데이터는 5분 구간 평균으로 합칩니다. 72개 구간 중 54개 이상, 30분 초과 결측이 없는 경우만 인정합니다. 최근 데이터도 75% 이상이고 마지막 기록이 30분 이내여야 합니다.
- 같은 설정의 서로 다른 날짜 3개 이상, 목표 온도 범위 유지율 80% 이상, 관측한 1시간 온도 하강 최대 2℃ 이하를 충족해야 추천합니다.
- 목표 범위 유지율, 범위 밖 편차, 급강하 순으로 비교합니다. 출력 %가 작다는 이유로 우선하지 않습니다.
- 이상 관찰·관찰 미확인·서로 겹치는 기간은 제외합니다. 설정 한 종류만 조건을 만족하면 그 사용 사례만 후보로 표시합니다.

이는 초기 비교 기준이며 검증된 축산 표준이나 인과 모델이 아닙니다. 과거에 실제 기록된 그룹 설정 조합만 표시하고, 새로운 온도나 %를 외삽하지 않습니다. 공기질·습도·돼지 건강·실측 풍량 적정성은 판정하지 않습니다. 데이터가 없거나 부족하면 임의의 추천값 대신 보류 이유를 표시합니다.

온도 기록은 기존 RTDB `history_logs`에서 해당 관찰 날짜 및 최근 6시간을 한국시간 하루 단위로 읽습니다. 선택 배치의 실내 온도와 외기 온도만 분석에 사용합니다. 데이터 조회 오류가 나면 부분 결과로 추천하지 않습니다. 화면을 닫아도 HA의 기존 온·습도 수집은 별도로 계속되며, 실제 컨트롤러 설정은 사람이 기록해야 합니다.

## 검증

`node tests/ventilation-learning.test.cjs` : 추천 성립, 조건 불일치, 결측·중복·오래된 센서, 과냉각·목표 이탈, 입력 검증.

`node tests/ventilation-journal.test.cjs` : 확인 없는 저장 방지, 누적·재로딩, 클라우드 실패 시 로컬 보관, 같은 ID 재전송, 빈 값 검증. Firebase 어댑터를 대체한 테스트이며 운영 DB에 가상 기록을 쓰지 않습니다.
