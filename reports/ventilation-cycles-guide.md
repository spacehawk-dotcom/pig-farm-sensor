# 입식 회차별 환기 기록

## 사용
- simu 앱에서 육성사 배치를 선택합니다.
- `입식 회차별 설정·온도 기록`에서 입식 회차를 선택하고 `회차 기록 보기`를 누릅니다.
- 입식부터 두수 0 변경까지를 한 회차로 묶습니다. 실제 설정 저장 시 현재 회차 ID를 함께 보관합니다.
- `등록 전` 회차는 사육현황의 입식일에서 표시한 미등록 회차입니다. `현재 입식 회차 등록` 버튼을 누르거나, 실제 기록을 저장하거나, 자동 수집 서버가 실행되면 등록됩니다.
- 종료된 회차는 새로운 입식 이후에도 별도로 남습니다. 빈 돈방도 과거 회차를 조회할 수 있습니다.
- 설정 관찰 기간의 실내 최저/최고/첫값 대비 끝값 변화와 표본 수, 30분 초과 공백을 표시합니다. 온도 변화의 인과관계를 판정하지 않습니다.
- 기존 실제 기록은 입식~종료 기간 안에 완전히 포함된 경우에만 해당 회차에 표시합니다. 경계를 넘는 기록은 임의로 나누거나 다른 회차에 넣지 않습니다.

## 데이터
- Firestore `farms/sungamfarm/ventilation_cycles/{cycleId}`: 입식일, 종료 시각, 돈방, 상태.
- `ventilation_cycle_state/{room}`: 현재 회차 포인터.
- 회차 하위 `temperature_days/{한국날짜}`: 날짜별 실내·외기 온도 원본 표본. 동일 타임스탬프는 중복되지 않습니다.
- 회차 하위 `settings/{timestamp}`: 사육현황 문서 변경 시의 앱 공유 수정 설정. 실제 컨트롤러 확인 기록과 구분합니다.
- 기존 `ventilation_records`의 신규 기록에는 `cycleId`, `cycleStart`를 추가합니다. 기존 데이터는 삭제하지 않습니다.
- 조회 시 현재 RTDB 기록과 보관 온도를 합칩니다. 서버에 등록된 회차는 조회한 과거 온도를 날짜별로 추가 보관합니다. RTDB에 남아 있지 않은 과거 자료는 복원할 수 없습니다.
- 첫 설치 이전에 입식·출하가 모두 끝난 회차는 재구성할 근거가 없습니다. 새 서버는 첫 센서 수신 시 이미 사육 중인 돈방을 등록합니다.

## 배포 상태 (2026-10-04)
- 로컬 코드/화면 및 회차·기록 테스트 완료.
- Firebase 프로젝트 접근은 확인했으나 자동 함수 배포는 무료 요금제 제한으로 실패했습니다.
- Blaze 요금제 전환은 수행하지 않았습니다. 현재 서버 자동 종료/지속 보관이 가동 중이라고 볼 수 없습니다.
- 현재 육성 1배치(2026-09-01 입식)를 실제 Firestore 회차로 등록해 검증했습니다. 임의 설정이나 가짜 두수는 저장하지 않았습니다.
- 공개 Netlify 화면에도 별도 배포가 필요합니다.

## Firebase 함수 배포
요금제를 사용자가 직접 확인·변경한 뒤:

```powershell
npm ci --prefix firebase-functions
firebase deploy --project sungamfarm --config firebase.cycles.json --only 'functions:trackGrowerCycle,functions:archiveCycleTemperature'
```

기존 전체 함수를 덮어쓰지 않도록 위 두 함수만 대상으로 배포합니다. `us-central1`의 기본 RTDB 인스턴스를 대상으로 합니다. Firebase 서비스 계정 및 이벤트 서비스에 필요한 권한은 배포 환경에서 확인해야 합니다. 읽기/쓰기 규칙은 자동 변경하지 않습니다. 클라이언트의 회차 및 온도 보관 컬렉션 접근은 농장 사용자에게 허용되어야 합니다.

배포 후 실제 두수/입식 데이터를 임의로 바꾸어 테스트하지 마세요. Emulator 또는 별도 테스트 프로젝트에서 입식→0두→재입식 및 RTDB 이벤트를 검증한 후 정상 센서 수신으로 현재 회차 생성과 온도 보관 여부를 확인하세요.
